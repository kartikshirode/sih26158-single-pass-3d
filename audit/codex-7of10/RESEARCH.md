# Options for a 7/10 model

These are experiments, not achieved gains. B1 is the 18.9 s real demo, B5v is the 600 s synthetic video. Times below are **predictions** of *additional* work against their saved 264.5 s and 502.2 s runs, based on the prior TX/Q timings or a bounded small trial. A dash in a licence column means there are no weights. Disk figures are proposed caps, not measured package downloads unless labelled exact. Windows means native Windows, no WSL. Gate every new dependency's transitive licence before product use.

OpenMVS 2.4's [global and local seam code](https://github.com/cdcseacave/openMVS/blob/v2.4.0/libs/MVS/SceneTexture.cpp) builds colour constraints then Poisson blends patches. The CPU failure in Q1 rules out CUDA alone. A deterministic diagnostic build with solver status is the shortest route to its cause. OpenMVS's latest tagged release must be checked again before changing builds; changing builds is not a measured fix.

## 6. Speed where quality costs time

The saved B5v v3 run spends 471.6 of 502.2 s in S3, with 135.9 s densify, 78.7 s mesh and 111.1 s texture. A proposed extra 300 s can still fit 900 s at 1 fps, but the real 30 fps ten-minute estimate is 615-700 s before that extra work. Therefore any quality branch adding more than roughly 200 s to B5v must replace time elsewhere or remain an optional judge view. Do not silently relax the time bar. `gsplat` is offline presentation work, not part of the timed six-format reconstruction.

| 6 | Trimmed Poisson only on visible orange holes | Could close gaps, but TX3 shows high wrong-surface risk. |
| 7 | ALIKED/LightGlue, only if B1/B2 have source overlap and ONNX-compatible build | New features cannot repair no-parallax regions; install risk. |
| 8 | texrecon, only if patch offsets and OpenMVS diagnostics fail | Complicated Windows build and camera conversion. |
| 9 | SRT exposure and focal-mode priors | Metadata availability and mode calibration limit immediate score. |

No proposed option changes an accuracy or held-out number until a clean end-to-end run verifies it. The 7/10 claim can be earned by a smaller set of passing changes; it does not require adopting every technology here.
