# Audit context: SIH26158 single-pass drone video to 3D

Reference material for the audit described in `audit/codex/PROMPT.md`. Read this once before
starting, then come back to it when you need a fact. Where this file and the code disagree,
the code is the authority and the disagreement is worth reporting.

Everything here was checked against the repository on 2026-09-24 at branch `codemap`
(commit cc79851, which is master 38f803e plus the codemap). Items marked "unverified" are
leads, not findings.

---

## 1. What the system is for

Smart India Hackathon 2026, problem statement SIH26158 (PS 17), set by the National Technical
Research Organisation. Input: one monocular drone video from a single flight pass, plus GPS
and flight metadata. Output: a georeferenced, metrically accurate, textured 3D model.

The binding targets exist only in `docs/SIH26158.pdf` (image-only). The requirement IDs used
all over the code come from `docs/01-SRS-requirements.md`:

| ID | Target | Status today (per docs) |
|---|---|---|
| R-O1 | 3D mesh or point cloud | met |
| R-O2 | under 15 min for a 10-min video | not met on CPU; no GPU timed; no 10-min clip ever ingested |
| R-O3 | spatial accuracy 1 m or better, absolute and georeferenced | met on synthetic RTK only; not measurable on real clips (no clip with GNSS) |
| R-O4 | entire visible scene | partially; facades limited by single pass |
| R-O5 | OBJ, PLY, LAS, GeoTIFF, glTF/GLB, FBX | all written |
| R-O6 | web or desktop viewer | yes |

Scoring weights: accuracy 30, completeness 20, speed 20, innovation 15, scalability 10, UI 5.
The dataset arrives on the day of the finale, so an unknown clip must never crash the system
and must never produce a confident wrong number.

The project's own stance, which the code is supposed to enforce: never print a metre that has
not been validated from outside the model; report absolute and aligned error separately;
a run always returns something labelled, even if that is "not reconstructable".

## 2. Architecture in one screen

Stages (contracts in `docs/09-interface-contracts.md`, code in `src/tesseract/stages.py`):

```
S0  screen        admissibility (src/ingest/screen.py)
S1  ingest        PyAV decode, crop, shots, DJI SRT telemetry, keyframes (src/ingest/video_ingest.py)
S2  plan          pose set and dense set
S3  geometry      MapAnything (mapanything_job/), or "adopt" a previous run, or "sense" on synthetic
S3b bundle adjust COLMAP (mvs_job/run_mvs.py via src/pipeline/colmap_export.py)
S4  dense + scale OpenMVS densify/mesh/texture; scale service (src/tesseract/scale.py)
S5  georeference  5-DOF yaw+translation+scale fit to GNSS in local ENU, EGM2008, UTM last
S5b level         F3/F4 to F5 via gravity estimate, applies the calibration factor once
S6  export        seven files in one frame (src/pipeline/export_formats.py, stages.Export)
S7  score         src/eval3d/metrics.py, synthetic only
S8  verdict       three-valued: met / not met / not measurable, per R-O target
```

Three runtimes share this code:

1. **Local orchestrator.** `python tesseract.py run <clip|synthetic>`. `src/tesseract/pipeline.py`
   runs the stage DAG with content-addressed resume (`state.json`), a time budget and the
   degradation ladder (L0 full ... L5 screen report only). Output: `out/runs/<name>/` with
   `run_manifest.json` (schema `sih26158/run-manifest/1`), `qa_report.md`, `export/`.
   `tesseract.py verify <rundir>` checks a run against its own contracts.
2. **Web upload path.** `demo/run/index.html` -> `demo/api/runs.js` (signed PUT URL) ->
   browser PUTs to `gs://sih26158-mumbai/web/<runId>/source.<ext>` -> `demo/api/start.js`
   starts Cloud Run job `sih26158-run` (`run_job/run_upload.py`, env `RUN_ID`) -> S0, S1 in
   process -> child job `kolu-ma` (MapAnything) -> `tools/finish_kolu.py` (preview) -> child
   job `sih26158-mvs` (`mvs_job/run_mvs.py`) -> `tools/finish_mvs.py` (final). The browser
   polls `demo/api/status.js`, which proxies `web/<runId>/status.json`
   (schema `sih26158/web-run/1`). Downloads go through `demo/api/file.js` (302 to a signed
   URL). This path deliberately bypasses the tesseract ladder. No auth: the 128-bit run id
   is the only capability. Limits: 1 concurrent run, 12 per day, 600 MiB, 10 min, 60 views,
   kill switch `PAUSED=1`.
3. **Legacy synthetic job.** `cloud_job.py` + root `Dockerfile` run
   `src/pipeline/run_demo.py` (simulated depth, not MapAnything). Its manifest uses old flat
   keys that `viewer/index.html` still reads.

Static site: `demo/` on Vercel (region bom1, Node 22 functions, 30 s cap). Every
`demo/**/index.html` except `viewer/` is generated by `tools/build_*.py` from
`tools/*_template.html` (Q&A is generated from strings inside `tools/build_qa.py`).

## 3. Contracts and invariants the code must hold

These are the rules to test the code against. Source in brackets.

### 3.1 Frames (docs/09 section 1, src/tesseract/contracts.py)

| ID | Name | Units | Notes |
|---|---|---|---|
| F0 | source pixel | px | full decoded frame |
| F1 | model pixel | px | MapAnything's centre-cropped, resized grid |
| F2 | camera | model units | OpenCV convention (x right, y down, z forward) |
| F3 | model world | model units | not gravity-aligned |
| F4 | refined world | model units | same gauge as F3; BA refines, does not re-frame |
| F5 | local level frame (LLF) | model units x scale.factor | up is gravity, heading arbitrary; NOT ENU |
| F6 | local ENU | metres | GNSS only |
| F7 | projected | metres | UTM EPSG:32642-32647 + EGM2008 height (EPSG:9518) |

- F4 to F5: gravity up-vector plus `scale.factor`, applied once.
- F5 to F6: 5-DOF yaw-only Sim(3). A 7-DOF fit is refused (`Code.REF_7DOF`).
- `georeferenced = true` only with frame F6 or F7.
- The fit is solved in local ENU and projected to UTM last (UTM carries about 0.6 m/km
  scale error across India).
- Ellipsoidal heights must become EGM2008 orthometric heights. PROJ silently returns the
  height unchanged when the grid is missing, so the code must raise instead
  (`Code.REF_BALLPARK`). EGM96 (EPSG:9707) must never be chosen by accident; EGM96 vs
  EGM2008 differ by 1.68 m at Amritsar.

### 3.2 Scale (docs/08, docs/09 section 2, ADR-014)

- Scale status is one of `unvalidated`, `calibrated`, `gnss`, `gnss+rtk`.
- `units_for(status)`: only `calibrated`, `gnss`, `gnss+rtk` may print metres. `unvalidated`
  prints "model units" everywhere: manifest, QA report, exports' metadata, console, gallery,
  demo, measure tools.
- Calibration files: `research/calibration/<clip>.json`, schema
  `sih26158/scale-calibration/1`, fields `runs, factor, bracket, status, method,
  references, floor_checks`. A run appears in at most one file. There is no global default
  factor.
- The factor is applied exactly once, at S5b/S6 export. Rendering never sees it; only
  measurement multiplies by it (viewer data contract: metres per shader unit =
  `D.scale * 32767 / 32000`, times the factor for measurement only).
- `research/calibration/kolu.json`: factor 5.54, bracket 5.32-5.77, runs `kolumvs3d`,
  `kolu3d`. Kolu was measured 5.3-5.8x too small before this (EXP-14).
- `research/` is in `.gcloudignore`, so container builds never see calibrations and their
  runs stay `unvalidated`. That is intended.

### 3.3 Georeferencing maths (src/eval3d/gnss.py, ADR-008, ADR-020)

- `yaw_only_sim3(src, dst)` assumes both point sets are already gravity-aligned with Z up.
  It solves yaw from XY only, then a least-squares scale, then translation. Returns
  `(R, t, s)`.
- `robust_yaw_sim3` is RANSAC around it with a MAD-derived "auto" threshold. Returns
  `(R, t, s, inliers)`.
- `src/pipeline/window_fuse.py` returns `(s, R, t)`: the opposite order. Every call site
  must use the right order.
- EXP-09: a full 7-DOF fit on a straight pass gives scene error 267-311 m even with RTK;
  yaw-only gives 0.041 m with RTK and 3.7 m with consumer GNSS.
- EXP-05: consumer GNSS absolute error about 4.1 m, flat from 50 to 2400 frames; RTK 0.097 m.

### 3.4 Evaluation harness (src/eval3d/metrics.py, ADR-003, ADR-022)

- Every result is reported twice: ABSOLUTE (no alignment; this is what R-O3 is judged on)
  and ALIGNED (after trimmed ICP). Alignment never fits scale.
- ICP was measured flattering a 2.68 m offset down to 0.21 m (12.8x). A 7-DOF alignment
  scores a 5%-too-small model at 0.000 m. Any path that reports only aligned error, or that
  lets scale into the alignment, defeats the harness.
- Completeness is reported against two denominators: observable surface and whole scene.

### 3.5 Telemetry (src/ingest/video_ingest.py, research/04-dji-srt-formats.md)

- Five DJI SRT families. `abs_alt` is barometric and must never be treated as GNSS height.
- Records are matched to frames by `FrameCnt` (1-based, so source frame index i maps to
  FrameCnt i+1), else by nearest time within one record interval, else not at all. Never
  positional.
- S1 decodes twice: an analysis pass at 0.25 scale, then a second decode of only the
  selected frames at full resolution (memory fix of 2026-09-23, `research/08-web-upload.md`).
  The second pass must return exactly the frames the first pass selected.

### 3.6 Orchestrator (src/tesseract/pipeline.py, docs/13 section 5)

- A budget overrun or a non-fatal `StageError` steps down one ladder level and restarts from
  stage 0. Fatal errors stop the run. A run always ends with a manifest.
- Resume is content-addressed through `state.json`. Changing an input, a config value, a
  stage version or the ladder level must invalidate the cache for that stage and everything
  downstream.
- `tesseract calibrate` writes a calibration JSON and says it takes effect on the next run.

### 3.7 Web path (run_job/run_upload.py, demo/api/*.js, research/08-web-upload.md)

- A screener refusal is a result (state ends at L5 with reasons), not an error.
- `status.json` is the only thing the browser reads; it is rewritten after every transition.
- Limits must agree across `demo/api/_lib.js`, `run_job/run_upload.py` and
  `tools/build_run.py`.
- Imagery must stay in asia-south1: the browser uploads straight to GCS, functions run in
  bom1.
- Preview output prefix `web/<runId>3d/`, final `web/<runId>mvs3d/`; `file.js` must map to
  exactly those.

### 3.8 Data residency and licences (docs/16, ADR-005, ADR-010)

- Compute and storage in India only (GCP asia-south1/asia-south2).
- OpenMVS (AGPL-3.0) runs unmodified as a separate process.
- Only the Apache MapAnything checkpoint (`facebook/map-anything-apache`) is allowed. VGGT,
  MASt3R, UniDepth, Inria 3DGS/2DGS, Pi3 weights and the CC-BY-NC MapAnything checkpoint are
  barred from any product build.

## 5. Leads from a pre-read (unverified)

Found while preparing this audit, not yet tested. Start here, but confirm or refute each one
before it goes in the report. They are hypotheses; several may turn out fine.

1. **The synthetic georeferencing test cannot see a missing levelling step.**
   `stages.Geometry._sense` (around line 284) and `src/pipeline/run_demo.py` (around line
   196) put the "reconstruction" in an arbitrary frame that differs from truth by a yaw
   rotation and a translation only, with scale exactly 1.0. So the input to S5 is already
   gravity-aligned and already metric, which is exactly what `yaw_only_sim3` assumes. A real
   F3/F4 frame is neither. Meanwhile S5-georef runs before S5b-level, and S5b skips when
   `points_geo` exists. Questions: once gap C-3 is closed, what levels a real frame before
   the yaw-only fit? Does the published synthetic RTK figure (0.098 m, README "Measured
   results") depend on this? A quick check: add a 5 degree roll and a 0.18 scale to the
   synthetic arbitrary frame and rerun the fit.
2. **Float32 on projected coordinates.** UTM northings over India are around 1e6 to 4e6 m,
   where float32 spacing is 0.125 to 0.25 m, and a later cast can quietly eat a large slice
   of the 1 m budget. Find every place F6/F7 coordinates are cast, saved, written to PLY/LAS/
   glTF, or quantised for a viewer, and check the dtype and offsets.
3. **Stale resume after recalibration.** `tesseract calibrate` writes a new calibration
   file. Does the cache key of the scale and export stages include the calibration file's
   content? If not, a resumed run could serve old units under a new status.
4. **Telemetry frame index semantics.** `telemetry_for_frames` maps source frame index i to
   FrameCnt i+1. Check that the indices passed in are absolute source-frame indices after
   `skip_start_s`, shot selection, the second decode pass and any crop, and what happens on
   variable-frame-rate video where `i / fps` is not the frame's timestamp.
5. **Upload API abuse surface.** `demo/api/runs.js` mints a signed PUT URL with no
   `x-goog-content-length-range`, and minting is not counted against the daily cap (only
   started executions are). `runningCount`/`startedToday` read one page of
   `listExecutions` with no visible page size. `runs.js` and `start.js` check concurrency
   and then act, so two clients can race. 500 responses return the raw exception message.
   Weigh each for real cost or exposure, not theory.
6. **Two calibration readers.** `src/tesseract/scale.py` and `tools/scale_cal.py` both look
   up calibrations. Do they agree when a run appears in two files ("first in sorted order
   wins" in one), on status validation, and on bracket handling?
7. **Axis swap handedness.** `export_formats` swaps glTF/GLB to Y-up and keeps other formats
   Z-up. Check the swap is a proper rotation (determinant +1) and that triangle winding and
   normals survive. Same question for `viewer/index.html` rotating a Z-up UTM mesh.
8. **GeoTIFF orientation.** `stages.Export` writes the DSM with `np.flipud` and
   `from_origin(e0, n0 + ny*res, res, res)`. Check the row order against the origin, the
   half-pixel convention, and the nodata value (`run_demo` fills with `-inf`, the stage
   uses NaN).
9. **Crop-aware intrinsics.** `colmap_export.full_frame_camera` maps intrinsics from the
   model's centre-cropped grid back to the full keyframe. S1 can crop keyframes for a
   burned-in overlay or the horizon, which is not a centred crop. Check the principal point
   and the 8% off-centre guard in that case.
10. **Completeness denominators.** Check that `metrics.evaluate` and the S7/S8 verdicts use
    the observable-surface and whole-scene denominators the way ADR-022 says, and that R-O4's
    verdict cannot be "met" from the flattering one alone.

## 8. Glossary

- **LLF**: local level frame, F5. Gravity up, arbitrary heading.
- **Model units**: lengths in the reconstruction's own scale; not metres until a ruler or
  GNSS says so.
- **Ladder**: L0 to L5 quality levels; the achieved level is written to the manifest.
- **Adopt**: S3 provider that takes geometry from an earlier run's `out/<run>/`.
- **Sense**: S3 provider for synthetic sources: visibility-sampled ground truth plus noise.
- **Kolu, Toolse, Village, Nicosia, Bahai**: development clips. Village was withdrawn for
  rights reasons and must not appear on any public surface (`WITHHELD` in build_console).
- **EXP-nn**: experiments registered in `docs/12`; results in `research/`.
- **ADR-nnn**: decisions in `docs/10`.
